# Аудит программы «Канон» по стандартам (16.10.2026)

**Стандарты:**
- ISO/IEC 25010 — качество программного продукта, 8 характеристик;
- OWASP ASVS 4.0.3, уровень 2, и OWASP Top 10 2021 — безопасность;
- WCAG 2.2, уровень AA — доступность;
- ISO 21001, ESG 2015, WFME 2020, IAAR — что программа покрывает из требований к системе качества вуза.

Тексты стандартов не цитируются, указаны только номера пунктов.

**Метод:**
- независимая проверка кода по безопасности: каждая находка прослежена по коду и проверена пробой;
- автоматические проверки:
  - `manage.py check --deploy`;
  - `pip-audit` (уязвимости в библиотеках);
  - `bandit` (статический анализ кода);
  - `coverage` (покрытие кода тестами);
  - `axe-core` (доступность) — 20 страниц, светлая и тёмная темы;
  - замеры числа запросов к базе и времени ответа на демо-базе (59 кафедр);
- матрица соответствия стандартам образования: построена по коду, моделям и адресам страниц.

**Что сделано правильно** (подтверждено проверкой):
- права на каждый объект проверяются отдельной функцией;
- нет изменений данных через GET;
- защита от подделки форм (CSRF) работает;
- формы с явными списками полей;
- нет небезопасного вывода HTML;
- файлы выдаются после проверки прав;
- анонимность студентов устроена правильно: нет связи «код → ответ», нет времени ответа, оценки хранятся счётчиками, есть порог показа и модерация текстов;
- рабочие настройки: HTTPS, Secure-cookies, HSTS;
- без ключа SECRET_KEY программа не запускается.

## 3. Доступность (WCAG 2.2 AA)

До правки axe-core нашёл:
- 1364 элемента с недостаточным контрастом (п. 1.4.3): бледный серый текст iOS имел 3,5:1 при норме 4,5:1;
- поле без подписи (п. 4.1.2);
- пустые заголовки столбцов (п. 1.3.1);
- ссылки, отличимые только цветом (п. 1.4.1).

**После правки — 0 нарушений** на 20 страницах в обеих темах. Цвета подобраны с сохранением стиля iOS. Тест проверяет контраст основных пар цветов в обеих темах и отсутствие пустых заголовков, чтобы будущие правки не ухудшили доступность незаметно.

Также сделано:
- кнопки и поля не меньше 40–46 px (п. 2.5.8);
- видимая рамка фокуса для клавиатуры;
- учитывается настройка «уменьшить движение».
