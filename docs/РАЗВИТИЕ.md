# Развитие «Канона» и порядок обновления

Разбор от 15.10.2026: что уже есть, чего не хватает по сути и как обновлять программу, нормы и данные.

## 1. Суть программы

«Канон» — это цикл качества, построенный как в медицине. В терминах ISO 9001 это PDCA: планируй, делай, проверяй, улучшай.

**Норма → обследование → находка → диагноз → лечение → контрольное обследование**

Сейчас этот цикл замкнут: каждое звено есть и работает. Но у программы пока есть четыре слабых места.

| Как в медицине | Что сейчас в «Каноне» | Чего не хватает |
|---|---|---|
| История болезни, динамика | Отдельные проверки | **Медкарты кафедры по годам**: «было — стало», тренды |
| Профилактика, ранние признаки | Отклонение видно, только когда показатель уже ниже порога | **Предупреждения о падении**: показатель снижается два года подряд |
| Синдром — сочетание признаков | Диагноз ставится по одному показателю | **Сочетания**: низкая удовлетворённость + слабые занятия + низкая качественная успеваемость → методическая проблема |
| Сортировка больных по тяжести | Проверки назначаются вручную | **План проверок по риску**: кого проверять первым |
| Здоровые привычки, а не только болезни | Находки — в основном отклонения | **Библиотека лучших практик**: сильные стороны кафедр, которые можно перенять |

Главный пробел относительно **Стратегии 2030** — приоритет 4, показатели 4.2 и 4.3. Стратегия требует, чтобы у ключевых процессов были владелец, показатели, карта рисков и механизм улучшения. В «Каноне» пока нет **реестра процессов СМК**. Это раздел 4.4 ISO 9001 — официальной основы системы качества ТГМУ. Без него показатель 4.3 приходится вносить вручную, и обосновать его нечем.

## 2. Предложения по улучшению (по порядку важности)

| № | Что | Зачем | Объём |
|---|---|---|---|
| 1 | **История показателей кафедры**: показатели по годам, «было — стало» | Видно, помогают ли планы исправления и куда движется кафедра | Небольшой |
| 2 | **Реестр процессов СМК** (ISO 9001, раздел 4.4): процесс → владелец → показатели → риски → улучшения | Прямо закрывает показатели Стратегии 4.2 и 4.3, нужен для IAAR (8.4.2) | Средний |
| 3 | **План проверок по риску** и **анализ со стороны руководства** (ISO 9001, разделы 9.2 и 9.3) | Центр из 3 человек проверяет в первую очередь тех, кому хуже. Решения руководства фиксируются и контролируются | Средний |
| 4 | **Меньше ручного ввода**: годовой отчёт заполняется заранее из портфолио и прошлого года; сотрудники загружаются списком из Excel | Кафедры не вводят одно и то же дважды | Средний |
| 5 | **Напоминания в Telegram** (или по почте): сроки, просрочки, «сдайте отчёт» | Без напоминаний сроки срываются | Средний; нужен бот, его создаёт владелец |
| 6 | **Опросы выпускников и работодателей**, учёт трудоустройства | Требуют IAAR (7.4, 8.6.2) и Стратегия | Небольшой: опросы уже есть |
| 7 | **Анализ экзаменационных тестов** (трудность, различающая способность, надёжность; загрузка из Excel) | Качество оценки студентов: IAAR, стандарт 3 | Средний |
| 8 | **Сочетание признаков**: проблема качества по нескольким показателям сразу | Точнее проблема — точнее план исправления | Небольшой |
| 9 | **Библиотека лучших практик** из сильных сторон | Кафедры учатся друг у друга | Небольшой |
| 10 | **Помощник ИИ** (позже, по решению владельца): сводка комментариев студентов, черновик текста самоотчёта | Экономия времени Центра. Только обезличенные данные, окончательный текст пишет человек | Средний |

**Состояние на 15.10.2026:** готовы пункты 1, 2, 3, 6, 7, 8, 9 (см. `ПЛАН.md`). Осталось: 4 (меньше ручного ввода), 5 (напоминания — нужен бот), 10 (помощник ИИ — по решению владельца).

Моя рекомендация: сначала **1 и 2**, они дают больше всего пользы. Потом **3 и 4**.

## 3. Как обновлять

Обновление бывает трёх разных видов.

### А. Программа (код)
1. Правки делаются в рабочей ветке GitHub. Все тесты должны проходить. Каждое исправление закрепляется тестом.
2. Новую версию сначала смотрят в **Codespaces** (демо), потом переносят в ветку `main`.
3. На сервере IT-отдел запускает `sudo /srv/kanon/app/deploy/update.sh`. Скрипт:
   - делает резервную копию;
   - забирает новую версию;
   - обновляет базу;
   - перезапускает программу и проверяет, что она работает.
4. Каждая версия получает номер и запись в журнале выпусков: что изменилось, что проверено.
5. Обычный ритм — раз в месяц. Срочные исправления — сразу.

### Б. Нормы и инструменты (содержание)
Это обновляет **Центр сам, мышкой**, без программиста:
- **Новая редакция стандарта** (ESG 2027 — ожидается в мае 2027; новое издание IAAR или WFME) добавляется как новая редакция документа. Старые проверки остаются привязанными к той редакции, по которой их проводили.
- **Инструменты** правятся через «Создать новую версию». Опубликованная версия не меняется.
- **Пороги** пересматриваются раз в год, в начале учебного года. Каждое изменение записывается в журнал.
- **Стратегия**: промежуточный пересмотр в 2027 году. Новые цели вносятся в справочник норм.

### В. Годовой цикл работы Центра (данные)
| Когда | Что |
|---|---|
| Сентябрь | Утвердить пороги на год; план проверок (по риску); уровни строгости кафедр |
| Октябрь — апрель | Проверки кафедр, планы исправления |
| Декабрь и май | Опросы студентов (после семестров) |
| Ежеквартально | Отчёты подразделений по Стратегии |
| До 5 июля | Годовые отчёты кафедр (по Положению 2018 г.) |
| Декабрь | Годовой стратегический отчёт Центра на Учёный совет (Word из «Канона») |
| Постоянно | Портфолио преподавателей, подготовка к аккредитации IAAR |

### Г. Перевод
После каждого обновления с новым текстом новые строки переводятся на таджикский. Носитель языка вычитывает файл `locale/tg/LC_MESSAGES/django.po`.

### Кто за что отвечает
- **Центр** (владелец): нормы, пороги, инструменты, справочники, проверки, вычитка перевода.
- **IT-отдел**: сервер, резервные копии, обновление по команде, перенос копий на другой носитель.
- **Разработка**: код, тесты, новые версии, инструкции.
