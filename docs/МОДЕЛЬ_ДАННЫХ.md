# Модель данных «Канона» (черновик)

Модель построена по итогам разбора кода открытых проектов (14.10.2026, подробности в [`ИССЛЕДОВАНИЕ_GITHUB.md`](ИССЛЕДОВАНИЕ_GITHUB.md)).
Названия таблиц даны латиницей, как они будут в базе.

## Стек

**Django** (+ django-ninja или DRF для JSON API), **PostgreSQL**, фронтенд **Vite + vanilla JS**.

Почему Django, а не FastAPI:
1. Таблиц 30+, есть права и журналы. Django-админка даёт справочники (нормы, проблемы качества,
   оргструктуру) почти без кода.
2. Миграции и транзакции встроены. Транзакции нужны для анонимного голосования.
3. Автомат состояний `django-fsm-2` уже проверен в EvaP ровно на таком цикле.
4. Ближайшие образцы (EvaP, система аккредитации AMS) написаны на Django.

Нагрузка у университета небольшая, поэтому асинхронность FastAPI не нужна.

## 1. Структура и люди

- `org_unit(id, parent_id, kind[university|faculty|department], code, name, path)`, где `path` вида `/u/med/surgery/`.
  Путь всегда заканчивается на `/`, иначе проверка «своё подразделение» ошибается.
- `user(id, full_name, email, is_active, login_key, login_key_valid_until)`: вход по одноразовой ссылке, как в EvaP.
- `role_assignment(user_id, role, org_unit_id, valid_from, valid_to)`.
  Роли: admin, rector, qa_director, expert, dean, head, teacher, external_expert.
  Права: роль действует на своём `org_unit` и всём, что ниже по пути.
- `delegation(from_user, to_user, valid_to)`: «кто может действовать за меня» (идея EvaP).

Студент учётной записи не имеет: он входит в анкету по QR-токену.

## 2. Нормативы (с версиями)

- `framework(id, code, title)`: WFME, ESG, ISO 21001, IAAR, РТ, ТГМУ.
- `framework_version(id, framework_id, version, effective_from, status[draft|active|retired])`.
- `area` → `standard` → `criterion`: код, текст, порядок.
- `indicator(id, criterion_id, code, title, unit, direction[higher_better|lower_better],
  threshold_weak, threshold_medium, threshold_high, source_hint)`.
- `indicator_lineage(old_id, new_id)`: связь показателя старой версии стандарта с новой. Нужна, чтобы динамика не обрывалась.
- `level_profile(id, title)` + `level_assignment(org_unit_id, framework_version_id, level)`: какой уровень
  строгости действует для подразделения (по умолчанию тот, что задан университету).

## 3. Учебная программа (упрощённо, по мотивам Ilios)

- `program`, `course(org_unit_id, program_id)`.
- `learning_outcome(level[program|course|session], parent_id, competency_id)`: цели обучения связаны цепочкой
  «программа → курс → занятие → компетенция». К ним можно привязать находку.

## 4. Инструменты

- `instrument(id, kind[survey|checklist|visit_protocol|osce_station|data_form], title, owner_unit_id)`.
- `instrument_version(id, instrument_id, version, schema_json, status, locked)`. Здесь `schema_json` — формат SurveyJS,
  у каждого пункта есть своё свойство `indicatorId`.
- `instrument_item(instrument_version_id, item_name, indicator_id, weight)`: строится автоматически при публикации версии
  и даёт связь «пункт → показатель».

## 5. Проверки

- `inspection_cycle(id, title, framework_version_id, period_from, period_to)`.
- `inspection(id, cycle_id, org_unit_id, lead_expert_id, state, planned_at, closed_at, parent_inspection_id)`.
  `parent_inspection_id` заполняется у повторной проверки.
- `inspection_member(inspection_id, user_id, role[lead|expert|external|auditee])`.
- `instrument_run(id, inspection_id, instrument_version_id, mode[named|anonymous], opens_at, closes_at, min_respondents, qr_token)`.
- Ответы с именем (чек-лист эксперта, ОСКЭ): `response(id, run_id, respondent_id, submitted_at, data_json)`.
- **Анонимные ответы** устроены по схеме EvaP:
  - `run_voter(run_id, token_hash)` хранит только факт «этот токен уже ответил», без связи с ответом;
  - `answer_counter(run_id, item_name, value, count)` хранит счётчики, отдельных строк с ответами нет;
  - `answer_text(id UUID, run_id, item_name, text, original_text, review_decision[undecided|public|private|deleted])` хранит
    свободные ответы, их показывают только после модерации;
  - запись голоса делается в одной транзакции. Итоги показываются, только если голосов не меньше `min_respondents` (по умолчанию 5).
- `indicator_value(inspection_id, indicator_id, value, n, level, computed_at)`: уровень вычисляется по порогам.
- `evidence(id, inspection_id, criterion_id, file_or_url, version, uploaded_by)`: доказательства с версиями.
- `inspection_transition(inspection_id, from_state, to_state, by_user, comment, at)`: журнал всех переходов.

**Статусы проверки:** черновик → запланирована → утверждена директором → сбор данных → сбор закрыт →
разбор экспертами → проект заключения → кафедра ознакомлена → закрыта. Отдельно есть статус «отменена».
Возврат «разбор → сбор» возможен только с комментарием.

## 6. Находки, диагноз, лечение (CAPA)

- `quality_problem(id, parent_id, code, title, description, typical_actions)`: справочник «болезней образования» в виде дерева.
- `finding(id, inspection_id, criterion_id, indicator_id, kind[strength|nonconformity|observation|opportunity],
  severity[minor|major|critical], description)`.
- `diagnosis(finding_id, problem_id, root_cause_text, set_by)`: диагноз ставит эксперт, программа только предлагает.
- `capa(id, ref, finding_id, org_unit_id, owner_id, state, analysis, plan_text, effectiveness_criterion,
  effectiveness_result[effective|not_effective], effectiveness_comment, followup_inspection_id, due_date, closed_at)`.
- `capa_action(id, capa_id, type[immediate|corrective|preventive|improvement], title, responsible_id, due_date, state, done_at)`.

**Статусы CAPA:** черновик → анализ (нужен диагноз) → план подан → план утверждён (декан или директор) → выполняется →
мероприятия выполнены → проверка результативности → закрыто результативно. Другие исходы: «переоткрыто» или «отменено».

Защиты, по образцу модулей ISO от OCA:
- без плана нельзя перейти к выполнению;
- закрыть нельзя, пока не выполнены все мероприятия и не записана оценка результативности;
- если оценка «не результативно», CAPA переоткрывается сама.

## 7. Анализ экзаменов

Классические индексы считает своя функция на numpy: трудность, дискриминация по 27 %, исправленная
точечно-бисериальная корреляция, KR-20 и альфа Кронбаха. IRT берём из `girth` 0.8.0 с закреплённой версией.
Этот проект больше не развивается. Moodle в ТГМУ нет: результаты экзаменов будут вноситься или загружаться из Excel в «Канон».
