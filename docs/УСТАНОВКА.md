# Установка «Канона» на сервер университета

Инструкция для IT-отдела. Проверено 15.10.2026 на том же наборе, что будет на сервере:
Ubuntu 24.04, PostgreSQL 16, nginx 1.24, gunicorn, Python 3.12+.
Файлы установки лежат в папке `deploy/`. Пароли и ключи в репозиторий **не кладутся**, только в `/etc/kanon/kanon.env` на сервере.

## Что нужно заранее
- Сервер или виртуальная машина: 2 ядра, 4 ГБ памяти, 40 ГБ диска, Ubuntu 24.04.
- Адрес, например `qanun.tajmedun.tj`: в DNS запись A на IP сервера.
- Доступ в интернет с сервера на время установки (пакеты, сертификат Let's Encrypt).

## 1. Пакеты и пользователь
```bash
sudo apt update && sudo apt install -y python3-venv python3-dev postgresql nginx git certbot python3-certbot-nginx
sudo useradd --system --create-home --home-dir /srv/kanon --shell /usr/sbin/nologin kanon
sudo mkdir -p /srv/kanon/media /etc/kanon && sudo chown kanon:kanon /srv/kanon/media
```

## 2. База данных
```bash
sudo -u postgres psql -c "CREATE USER kanon WITH PASSWORD 'ПРИДУМАТЬ_ДЛИННЫЙ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE kanon OWNER kanon;"
```

## 3. Программа
```bash
sudo -u kanon git clone https://github.com/MirMed01/Avicenna-University-strategic-department-.git /srv/kanon/app
cd /srv/kanon/app
sudo -u kanon python3 -m venv .venv
sudo -u kanon .venv/bin/pip install -r requirements.txt
```

## 4. Настройки
```bash
sudo cp deploy/env.example /etc/kanon/kanon.env
sudo chmod 600 /etc/kanon/kanon.env
python3 -c "import secrets; print(secrets.token_urlsafe(50))"   # это KANON_SECRET_KEY
sudo nano /etc/kanon/kanon.env   # вписать ключ, пароль базы, адрес
```

## 5. Таблицы, начальные данные, первый администратор
```bash
set -a; . /etc/kanon/kanon.env; set +a
sudo -E -u kanon .venv/bin/python manage.py migrate
sudo -E -u kanon .venv/bin/python manage.py load_initial_data      # структура ТГМУ, Стратегия 2030, IAAR, инструменты
sudo -E -u kanon .venv/bin/python manage.py collectstatic --noinput
sudo -E -u kanon .venv/bin/python manage.py createsuperuser       # email и пароль администратора
sudo -E -u kanon .venv/bin/python manage.py check --deploy         # должно быть «no issues»
```
**Не запускать** `setup_demo` на рабочем сервере: она создаёт демо-входы. Без режима разработки она и не запустится.

## 6. Автозапуск и веб-сервер
```bash
sudo cp deploy/kanon.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now kanon
sudo cp deploy/nginx-kanon.conf /etc/nginx/sites-available/kanon   # заменить qanun.tajmedun.tj, если адрес другой
```
Сертификат HTTPS: сначала временно включить только блок `listen 80` (или выполнить `sudo certbot certonly --webroot -w /var/www/html -d qanun.tajmedun.tj`), затем:
```bash
sudo ln -s /etc/nginx/sites-available/kanon /etc/nginx/sites-enabled/kanon
sudo nginx -t && sudo systemctl reload nginx
curl https://qanun.tajmedun.tj/health/      # ответ: ok
```

## 7. Резервные копии (обязательно)
```bash
sudo crontab -e
# добавить строку:
30 2 * * * /srv/kanon/app/deploy/backup.sh >> /var/log/kanon-backup.log 2>&1
```
Копии хранятся в `/var/backups/kanon` 14 дней. **Раз в неделю переносите копию на другой носитель или сервер.**
Восстановление (проверено): `sudo -u postgres pg_restore -d kanon --clean файл.dump` и распаковка `kanon-media-…tar.gz` в `/srv/kanon`.

## 8. Обновление до новой версии
```bash
sudo /srv/kanon/app/deploy/update.sh
```
Скрипт сам делает резервную копию, забирает новую версию, обновляет базу и перезапускает программу. В конце он пишет «программа работает».

## Важно для безопасности
- Папку `/media/` nginx наружу не отдаёт: файлы портфолио и доказательств аккредитации выдаёт программа после проверки прав.
- Строгий HTTPS (HSTS) сначала включён на 1 день. Через 1–2 недели стабильной работы можно поставить
  `KANON_HSTS_SECONDS=31536000`. Поддомены сайта университета он не затрагивает.
- Учётные записи открывает администратор (страница «Пользователи»). Если человек забыл пароль, администратор задаёт новый в разделе `/admin/`.
- Адрес сервера и пароли не записывать в репозиторий и в документы проекта.
